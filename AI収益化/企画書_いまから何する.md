## 1. サービス概要

**時間・予算・気分から、「今から行ける場所」を横断して提案するサービス。**

| 項目 | 内容 |
|---|---|
| 対象 | 「今から数時間、空いてしまった」個人 |
| 入力 | 現在時刻／何時まで空いているか／予算／人数／気分（話したい・話したくない）／体を動かすか |
| 出力 | 今から間に合う選択肢を、**予約が要るもの・要らないもの両方**まとめて提示 |
| 収益 | 予約商材（アソビュー・じゃらん等）への送客手数料 |
| 必要資金 | **0円**（既存の1ファイル完結HTML方式・ホスティングは既存流用） |

---

## 2. 解決する課題

「今日、17時から21時まで空いた。何をしよう」——この状態で人が実際にやっていることは、

1. Googleで「大阪 遊び」と検索する
2. 大量の記事とランキングが出てくる
3. **開いている時間・予算・一人で行けるかが分からない**
4. 調べるのが面倒になる
5. **結局そのまま家に帰る**

**課題は「選択肢がないこと」ではなく「選択肢が多すぎて絞れないこと」。**

---

## 3. なぜ既存サービスでは解決できないのか

### 既存プレイヤー

| サービス | 規模 |
|---|---|
| **アソビュー！** | 全国6,000施設・400種類。アプリは620ジャンル・1万件以上。**当日予約に対応** |
| **じゃらん 遊び・体験予約** | ネット予約可能プラン数No.1・施設数No.1・利用率No.1。**当日予約の専用ページあり** |

**両社とも当日予約には既に対応している。** それでも上の課題が残るのは、構造的な理由がある。

### 構造的な限界：予約サイトは「予約できるもの」しか出せない

| ユーザーが本当に知りたいこと | 既存で出るか |
|---|---|
| 今17時から21時まで、予算3,000円で何ができる？ | **✕** 時間からの逆算検索がない |
| 一人で行っても浮かない場所は？ | **✕** |
| **予約不要で今すぐ行ける場所**（映画・銭湯・美術館・散歩） | **✕** 予約商材しか掲載されない |
| 今日は人と話したくない／話したい | **✕** |

**予約サイトは予約が発生しないと1円にもならないので、「予約不要の選択肢」を出す動機が構造的に存在しない。**

ここが本サービスの入る余地。**予約不要の選択肢も正直に出すからこそ信用され、結果として予約商材のクリック率が上がる。**

## 4. ソリューション

### 画面フロー

```
① 条件を6つ選ぶ（各1タップ・30秒）
   いま何時 / 何時まで / 予算 / 人数 / 気分 / 体を動かすか
        ↓
② 「今から間に合うもの」だけに絞り込む
   ・移動30分を見込んで、閉店時刻までに所要時間が収まるか
   ・予算の下限を超えないか
   ・一人で行って浮かないか
        ↓
③ スコア順に提示（予約要否のバッジつき）
   予約不要 → そのまま行ける（信頼の獲得）
   要予約   → 予約ページへ送客（★収益発生点）
```

### 実装済みの判定ロジック（デモで動作確認済み）

| 判定 | 内容 |
|---|---|
| **時間の逆算** | 現在時刻＋移動30分 ≦ 最終入店時刻（閉店 − 所要時間）を満たすものだけ表示 |
| 予算 | 下限が予算を超えるものは除外。上限が予算内なら加点 |
| ひとり適性 | 5段階。「ひとり」選択時は適性2以下を除外 |
| 気分 | 「話したくない」なら会話が主目的の業態を除外 |
| 体を動かすか | のんびり／運動で重みを反転 |
| 時間フィット | 空き時間に対して所要時間が6〜10割に収まるものを加点 |

**検証結果（デモ実行）**

| 条件 | 結果 |
|---|---|
| 17:00〜21:00／2,000円／ひとり／静か／のんびり | **19件**（1位：映画館・漫画喫茶・図書館） |
| 10:00〜18:00／5,000円／2人／話したい／動きたい | **19件**（1位：料理教室 ※要予約） |
| **22:00〜24:00／1,000円／ひとり** | **4件**（深夜・低予算では正しく絞り込まれる） |
| 予算0円 | 5件（図書館・散歩・展望台・モール・ランニング） |

**「22時から1,000円で何ができる？」に4件で答えられる。これは既存の検索では出てこない答え。**

## 5. 収益モデル

| 収益源 | 内容 | 単価目安 |
|---|---|---|
| **予約商材への送客** | アソビュー・じゃらん等のアフィリエイト | 予約額の数% |
| 施設の有料掲載 | 軌道に乗った後の追加収益 | 月額 |
| 地域特化の広告 | 同上 | — |

**ユーザーからは課金しない。** 無料で使えるからこそ「暇な時に開く」習慣ができる。

## 6. 数値計画

| 指標 | 数値 |
|---|---:|
| 目標 | **月10万円** |
| 平均送客単価 | 約2,000円 |
| 必要な成果件数 | **月50件** |
| 訪問→送客クリックのCVR | 10〜15% |
| **必要な月間UU** | **1,700〜3,300** |

### 到達までのスケジュール（正直な見積もり）

| 時期 | 状態 |
|---|---|
| 1ヶ月目 | MVP公開・ASP提携・知人10人で検証 |
| 2〜3ヶ月目 | SNS経由で数百UU／初回の送客発生 |
| **4〜6ヶ月目** | SEOが効き始める／**月10万円が視野** |

> **3ヶ月で月10万円は集客が間に合わない。6ヶ月が現実的な線**と見ています。

## 7. 開発計画

| フェーズ | 内容 | 期間 | 費用 |
|---|---|---:|---:|
| **0. 提携確認** | **ASP（アソビュー・じゃらん・楽天）の提携審査** | 1日 | **0円** |
| 1. MVP | デモを本番化。データを実在の施設に差し替え（1エリア・50件程度） | 3日 | 0円 |
| 2. 検証 | 知人10人に使ってもらい、入力完了率とクリック率を測る | 1週間 | 0円 |
| 3. 拡張 | エリア追加・データ拡充・SEO記事 | 継続 | 0円 |

**フェーズ0が最優先。** ASP提携が通らなければ、どれだけ良いものを作っても収益はゼロになる。**無料で今日できる。**

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| **データの鮮度**（営業時間・料金の変更） | 業態単位の一般値で出し、**個別店舗の断定はしない**。「〜21時ごろまで」等の幅で表記 |
| ASP提携が通らない | **着手前に確認する**（フェーズ0） |
| 集客が伸びない | SNSで「結果画面」を出す。**「22時・1,000円・ひとり」→4件**のような具体的な結果は拡散しやすい |
| 大手が同じ機能を出す | 予約サイトは**予約不要の選択肢を出す動機がない**ため、追随しにくい。ただし可能性はゼロではない |
| 情報の正確性へのクレーム | **「目安」「一般的な相場」と明示**。実在店舗の断定表示をしない |

---

## 9. なぜ当社がやるのか

| 理由 | 内容 |
|---|---|
| **開発コストがゼロ** | ルートの14本と同じ1ファイル完結方式。**デモは実際に2時間で完成した** |
| 営業が不要 | 検索とSNSから人が来る構造。当社の制約（営業が苦手・時間がない）に合う |
| 既存の集客資産がある | `www.social-quality.com` から導線を引ける |
| AIとの相性 | データ整備・SEO記事・スコア調整をすべてAIで回せる |
