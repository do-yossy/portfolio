# 落ちた人を次へつなぐ事業 ── 4条件すべてを満たす新規事業

> 作成：2026-08-31 ／ 条件：①大手が参入できない ②顧客の未来が良くなる ③みんなが広げてくれる ④テストマーケティングに成功

## 結論（先に3行）

1. **中小企業の採用運用を月額で丸ごと引き受け、そこで「不採用にした人」を本人同意のうえ他社へつなぐ。** 入口＝採用運用サブスク（月3〜5万円）、出口＝人材紹介（理論年収の30〜35%）の二段構え。
2. **入口の仕組みは既に動いている。** `kyujinbox-platform` が求人ボックスへの複数アカウント自動投稿・成績取得・AI改善・月次レポート自動生成まで実装済み。他社に向けるだけで限界費用はほぼゼロ。
3. **顧客が増えるほど紹介先の在庫が増える。** 20社の求人が、20社の不採用者の受け皿になる。後発が真似しづらいのはここ。

---

## 1. 何をやるか

```
① 中小企業と月額契約（月3〜5万円）
   → 求人ボックス／Indeed へ求人を自動投稿・AI改善・月次レポート

② 応募が来る → 架電・ヒアリング（既存の運用手順どおり）

③ その会社では採らない人が出る  ←★ ここが今、全国どこでも捨てられている
   → 電話面談の時点で「他社のご紹介もできますが」と同意を取っておく

④ 同意した方に、他の顧客企業の求人を案内 → 決まれば紹介手数料
```

**捨てられている資源を拾う事業。** 現在、不採用者はお祈りメール1通で関係が終わる。企業には後味の悪さだけが残り、応募者は振り出しに戻る。ここに値段がついていない。

### 対象

`kyujinbox-platform/seeds/` にある29本の求人がそのまま対象像を示している ── ルート配送・軽作業・機械オペレーター・EC倉庫・美容機器配送・シニア営業。**年収250〜350万円帯の現場職**で、採用に困っている中小企業。

---

## 2. 条件①：大手が参入できない

技術では守れない。**収益構造で守れる。**

### (a) 媒体大手とは利益が正面から衝突する

Indeed・求人ボックス・リクルートは**掲載またはクリックで課金する**。「早く決まって掲載を止める」ことを目的にしたサービスは、自社の売上を自分で削る。

証拠は既に社内にある。シニアジョブの規約は、応募者の社外誘導を**1人あたり300万円＋社名公表**で禁じている（`recruitment-platform/docs/seniorjob-operations.md` 第7条）。応募者を外に流す行為は、媒体にとって本業の破壊そのもの。だから媒体側からは絶対にこの事業を作れない。

### (b) 人材紹介大手には単価が低すぎる

年収300万円 × 30% ＝ **90万円/件**。大手紹介会社のコンサルタント1人あたり生産性では合わない帯域で、だから現場職の紹介は薄い。当社は既存システムで応募者が自動的に集まるため、1件あたりの獲得原価が桁違いに低い。

### (c) 顧客単価が小さすぎて営業が成立しない

月3〜5万円の零細企業に、大手の営業体制（1社獲得に数十万円）を当てると赤字。**リファラルで獲るしかない価格帯**であり、そこは条件③と噛み合う。

### (d) 参入されても後発が困るところ

紹介先の在庫が顧客数に比例して増える。10社の時と50社の時では、同じ不採用者に出せる求人の数が違う。**先に顧客を持った方が、後から入る者より必ず良い体験を出せる。**

---

## 3. 条件②：顧客の未来が良くなる

顧客が2人いて、両方の未来が良くなるのがこの形の特徴。

| | 今 | この事業の後 |
|---|---|---|
| **企業** | 掲載しても応募が来ない。来ても採らない人ばかりで、断るたびに気が重い | 応募が来る。採らなかった人にも次を用意できるので、断ることが後ろめたくなくなる |
| **応募者** | 落ちたら振り出し。また媒体を探し直す | 落ちても次が来る。1回の応募で複数社に届く |

### 「良くなった」を測る指標を1つ足す

月次レポートに、応募数・採用数に加えて

> **お見送りした方 ◯名 ／ うち他社で決まった方 ◯名**

を載せる。この行は他のどのサービスの帳票にも存在しない。**これが条件③の材料そのものになる。**

---

## 4. 条件③：みんなが広げてくれる

双方向の口コミが同時に立つ。片側だけのサービスには無い性質。

### 企業側

紹介が起きるのは「便利だよ」のときではなく、**成果を数字で言えるとき**（`ファンを作る設計.md`）。月次レポートが顧客の口を動かす台本になる。中小の現場職採用は商工会・同業・取引先の横のつながりが濃く、1社の実感が伝わりやすい。

### 応募者側

**落ちたのに次を決めてもらった体験は、語られる。** 現場職の求職者は元同僚・家族・友人の間で求人情報が回る層で、ここは求人広告より速い。

### ただし、求職者への謝礼は使えない

2025年1月から、職業紹介事業の**許可条件**に「求職者への金銭等（お祝い金）の提供禁止」が追加された。**求職者側リファラルに現金を出す設計は取れない。** 企業側への紹介割引は可（求職者への金銭提供ではない）。ここは最初から設計に織り込む。

---

## 5. 条件④：テストマーケティングに成功

正直に2段階で書く。**通っている部分と、まだ通っていない部分がある。**

### 通っている：型としての成功実績

「安いツールで入口をつくり、高い紹介で回収し、リファラルで広げる」── これは御社が Instagram 自動化ツールのサブスク販売で**実際に売れた型**。媒体が Instagram から求人媒体に変わるだけで、構造は当時と同一（`昔の型を今で再現する.md`）。

### 通っている：実装としての自社検証

`kyujinbox-platform` は稼働中で、以下が既に動いている。

| 機能 | 状態 |
|---|---|
| 求人票PDF（ZIP）をAIが読み取り登録 | 実装済み |
| 求人ボックスへ複数アカウント自動投稿 | 実装済み |
| 成績（閲覧・応募）取得 | 実装済み |
| 応募が無い求人のAI改善ループ | 実装済み |
| 月次レポートの自動生成（HTML/PDF） | 実装済み |
| 応募 → 架電 → 別求人の案内 という出口の運用手順 | 文書化済み |

**自社を最初の顧客としたテストは通っている。** 求人 seed は29本で、職種の当たりもついている。

### まだ通っていない：外部の他社が月額を払うか

ここだけが未検証。**だから最初は売らない。**

1. 既存の採用支援先1社に、無料で開放する（アカウント追加だけで済む）
2. 求人を登録 → 自動投稿 → 成績取得 → 月次レポートを3回送る
3. 3回目のレポートに「お見送り ◯名／うち他社で決まった ◯名」を初めて載せる
4. **そこで初めて月額3万円を提示する**

相手が価値を感じた後に価格を出すので、売り込みにならない。当時と同じ売れ方。

## 6. 数字

| | 計算 | 月額換算 |
|---|---|---|
| 採用運用サブスク | 月3万円 × 20社 | 60万円 |
| 人材紹介 | 年収300万 × 30% ＝ 90万円/件 × 年6件 | 45万円 |
| **合計** | | **月105万円** |

年6件の現実性：20社が各月5応募として月100応募・年1200応募。うち不採用が8割で960人。**そこから6件（0.6%）**。保守的すぎるくらいの数字で、紹介先の在庫が育てば数%は狙える。

**重要：初年度は紹介収益ゼロで黒字になる価格にすること。** 紹介がいつ出るかは読めない。サブスクだけで回る設計にしておき、紹介は上振れとして扱う。

## 7. 法令のゲート（ここが最大の前提）

### 有料職業紹介事業の許可

出口を自社でやるなら**必須**。

| 要件 | 内容 |
|---|---|
| 基準資産 | 資産 −（繰延資産・営業権）− 負債 ＝ **500万円以上**（事業所ごと） |
| 現金・預貯金 | **150万円以上**（事業所が増えるごとに60万円加算） |

### 許可が無い場合に取れる唯一の合法な形

**紹介そのものを他社に業務委託させることはできない。** 名義貸しは職業安定法32条の10違反。一方で**集客業務や事務作業（スカウトメールの代理送信・面接日程の調整など）の外注は認められている。**

→ したがって許可が無い間は、**当社が提携紹介会社から「集客・応募者対応」を受託する側に回る**。当社は紹介を行わず、紹介会社の集客を担う。報酬は業務委託費として受ける（成果連動の設計は慎重に）。

### 2025年1月改正で足す必要のあるシステム機能

- **自ら紹介して無期雇用で就職した人へ、就職日から2年間の転職勧奨は禁止。** → 架電リストに「紹介成立者・就職日」を記録し、2年間は架電対象から自動除外する仕組みが要る
- **求職者へのお祝い金の提供禁止** → リファラル設計に現金を使わない

### その他の絶対線

- **シニアジョブ経由の応募者は絶対に流さない**（1人300万円）。入口は求人ボックス・Indeed・自社サイトのみ
- 求人者（実際の雇用主）を明示。おとり求人にしない（職安法・景表法）
- **媒体の自動巡回・自動応募はやらない**（`CLAUDE.md` の恒久方針）。自社求人を自社アカウントで出す自動投稿は、これとは別の行為

## 9. 最初の90日

| 時期 | やること |
|---|---|
| 〜2週 | **有料職業紹介の許可の有無を確認**。無ければ提携紹介会社を1社探し、集客受託の形で契約 |
| 〜4週 | 既存の採用支援先1社に無料開放。アカウント追加・求人登録・自動投稿 |
| 1〜3ヶ月 | 月次レポートを3回送る。同意取得を電話面談に組み込む |
| 3ヶ月 | レポートに「お見送り後の決定数」を初掲載 → **月額3万円を提示** |
| 4ヶ月 | 2社目を1社目からの紹介で獲る（＝条件③が本当に回るかの検証） |

## 10. 正直な弱点

- **同意率が読めない。** 落ちた直後の人に「他社を紹介します」は感情的に受け入れられにくい。→ お見送り通知と同時ではなく、**電話面談の段階で先に同意を取る**設計にして回避する
- **紹介先の在庫が薄いうちは決まらない。** 顧客10社を超えるまでは紹介収益をあてにしない
- **許可が無いと出口が塞がる。** ここが未確認のままだと事業が半分しか成立しない
- **企業から「うちの応募者を他社に渡すのか」と言われる可能性。** 契約書に「不採用にした方のみ・本人同意必須・同業と同一商圏には回さない」を明記して先回りする
