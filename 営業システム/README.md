# 営業システム（Sales OS）— 半自動化Web制作事業

このフォルダは **役割1〜4（案件獲得 → 提案 → ヒアリング → 要件定義）＋見積もり** を仕組み化した営業オペレーティングシステムです。

> 目的：**「案件を貼れば即・分析〜提案〜見積もりが出る」再現性のある状態**を作り、人間工数を最小化して
> **月商100万円 / 利益率50%+ / 納期遵守95%+** を達成する。

## なぜ仕組み化するか（KPI連動）
| KPI | この営業OSでの効き方 |
|---|---|
| 月商100万円 | スコアリングで高単価・高受注率の案件に集中（→`05`の逆算モデル） |
| 利益率50%+ | テンプレ流用前提の案件選定＋見積もり時に手数料・工数を逆算 |
| 納期遵守95%+ | 要件定義（`04`）で制作順序と依存関係を先に固定 |
| 工数最小化 | 提案文・ヒアリング・見積もりをテンプレ化、毎回ゼロから書かない |
| 再現性 | 属人判断を排し、点数・閾値・テンプレで誰でも同じ品質 |

## 使い方（Claude＝COOへの依頼フロー）
1. **案件を貼る** → 「この案件、役割1で分析して」… `01-案件スコアリング基準.md` に従いスコア・優先度・応募可否・提案文を出力
2. **応募文が必要** → `02-提案文テンプレート.md` の該当タイプを変数差し込みで出力
3. **問い合わせが来た** → `03-ヒアリング・打合せ判定シート.md` で不足情報を質問化＋対応区分（AI/人）を判定
4. **受注確定** → `04-要件定義テンプレート.md` でサイトマップ〜制作順序を生成
5. **金額提示** → `05-見積もりロジック.md` でプラン＋オプション＋手数料・利益率チェック
6. ブラウザで `../営業案件管理ツール.html` を開けば、**1（スコアリング）・5（見積もり）・2（提案文生成）をフォーム入力で即計算**（API不要・オフライン動作）

## 🔄 学習ループ（案件をこなすほど賢くなる）
`学習/` フォルダが、AIが案件をこなしながら **受注率・単価・利益率を上げていく自己改善ループ** の中核です。

> **前提**：AIの記憶はセッションを跨ぎません。**このリポジトリが長期記憶**です。だから「学習」＝結果を記録し、データから基準・テンプレを更新し、`学習/インサイト.md` に蒸留すること。次のセッションは更新後の知識から始まります。

```
① 応募（01/02・予測受注率を記録）→ ② 応募ログ.jsonl に結果を追記
→ ③ node 学習/集計.js で可視化 → ④ 学習プロトコルに従い 01配点/02文面/インサイト を更新 → ①へ
```

| 学習ファイル | 役割 |
|---|---|
| `学習/README.md` | 学習ループの設計・スキーマ・運用規律 |
| `学習/応募ログ.jsonl` | 全応募の記録（学習データ・追記式） |
| `学習/集計.js` | ログ → KPI・キャリブレーション・改善提案（週次レポート＝役割8兼用） |
| `学習/学習プロトコル.md` | データから基準・テンプレを更新するルール（学習アルゴリズム） |
| `学習/インサイト.md` | 蒸留された知識（**セッション開始時に必読**） |

**集計コマンド**：`node 営業システム/学習/集計.js`（書式確認は `--all`）
**セッション開始の儀式**：案件処理の前に `学習/インサイト.md` と直近ログを読む → 過去の学習を引き継ぐ。

## 更新ルール（学習の蓄積＝再現性向上）
- 受注/失注のたびに「効いた提案文・刺さった訴求」を `02` へ追記
- 価格改定時は **`事業まとめ.html` / `05-見積もりロジック.md` / `営業案件管理ツール.html`** の3点を同時更新
- スコア基準が外れたら（受注率と乖離）`学習プロトコル.md` に従い `01` の配点を見直す
