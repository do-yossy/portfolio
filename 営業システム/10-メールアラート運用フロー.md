# 10 メールアラート運用フロー（案件発見→応募→学習）

求人アラートメールを起点に、**AIが取込〜応募キュー生成まで／人は提出15秒／AIが学習**まで回す実行フロー。

```
[案件取り込み]→[役割1スコアリング]→[提案文+価格+デモ自動差込]→[応募キュー生成]   ← ここまで全部AI
        ↓
[応募コックピット] 1画面で：コピー→案件ページ→貼って提出→[結果記録]            ← 人は15秒だけ
        ↓
[学習ログ書き戻し]→[集計.js]→[基準・テンプレ・インサイト更新]                  ← またAI（翌日より賢く）
```

## 担当と手順
| ステップ | 担当 | 具体 |
|---|---|---|
| ① 取り込み | AI | 求人アラートが届くGmailを私(Claude)が `from:lancers.jp` 等で読取り、案件を `sales-platform/data/inbox.json` に整形（`[{title,text,source,url}]`）。※あなたが本文を貼ってもOK |
| ② スコアリング | AI | `node sales-platform/scripts/build-queue.js`（役割1で採点・応募可否判定） |
| ③ 提案文+価格+デモ | AI | 同スクリプトが、応募推奨のみに提案文・見積価格・最適デモURLを自動差込 |
| ④ 応募キュー生成 | AI | `data/queue.json` を出力（スコア順）。中身を応募コックピットへ |
| ⑤ 提出 | **人(15秒)** | `応募コックピット.html` で 📋コピー→🔗案件ページ→貼って提出→[応募済み] |
| ⑥ 結果記録 | 人(数秒) | 受注/失注/返信なしをコックピットに記録→「学習ログ出力」 |
| ⑦ 書き戻し | AI/人 | `node sales-platform/scripts/append-log.js results.jsonl`（または手で `学習/応募ログ.jsonl` に追記） |
| ⑧ 集計→更新 | AI | `node 営業システム/学習/集計.js` →『学習プロトコル』に従い 01配点・02提案文・`インサイト.md` を更新 → 翌日のキューがより賢く |

## 初回セットアップ（1回だけ・あなた）
ランサーズ/CWの**新着案件メール通知**を `social.recruiting.information@gmail.com`（＝連携済みGmail）に届くよう設定。
推奨保存検索KW：`LP制作` `ホームページ制作` `予約システム` `業務効率化 ツール` `LINE構築` `AIツール 開発`（詳細は `09-売上ロードマップ.md`）。

## 毎日の回し方
1. あなた →「**Gmール確認して**」と一言（または案件を貼る）
2. 私 → Gmailから新着を取込み `build-queue.js` 実行 → **応募キューを提示**（見送り案件は理由つきで除外）
3. あなた → コックピットで**上から提出**（規約準拠・1件15秒）
4. 結果を記録 →「学習ログ出力」を私に渡す
5. 私 → `append-log.js`＋`集計.js` で学習更新 → 管制塔(`事業ダッシュボード.html`)で100万への進捗を確認

## コマンドまとめ
```bash
# ②〜④ 応募キュー生成（data/inbox.json → data/queue.json）
node sales-platform/scripts/build-queue.js

# ⑦ 学習ログ書き戻し（コックピット出力のJSONLを追記）
node sales-platform/scripts/append-log.js results.jsonl

# ⑧ 集計（学習）
node 営業システム/学習/集計.js
```
> `sales-platform/data/` は `.gitignore` 対象。実案件データ・生成キューはリポジトリに公開されません。

## 正直な線引き（不変）
- **提出（応募の最終送信）は人**：規約（自動応募禁止）＆本AI環境は外部ネット遮断でランサーズ等に到達不可。
- **案件発見はメール経由**：プラットフォーム自動巡回は行わない。
- それ以外（取込・採点・提案文・価格・デモ・キュー化・学習）は**AIが担当**。
