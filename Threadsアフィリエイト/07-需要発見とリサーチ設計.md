# 07 需要発見とリサーチ設計

この仕組みの本体は投稿ではなく**需要発見**。ここが正しければ凡庸な投稿でも売れ、ここを外すと名文でも売れない。

---

## 1. なぜその商品が売れるのか

**売れているのは商品ではなく「解決」。** 同じ商品でも、どの悩みに紐づけるかで結果が変わる。

例：フェイクファーのブランケット（3,480円）

| 紐づける悩み | 売れ方 |
|---|---|
| 「暖かい」 | ✗ 競合が多すぎる。価格比較になる |
| 「部屋に置くと生活感が出る」 | ◎ **インテリアの悩み**として売れる（動画の例） |
| 「猫がソファを傷つける」 | ◎ **ペットの悩み**として売れる（別の市場） |
| 「洗濯で毛が抜ける」 | ○ 既に買った人向け＝購買意図が弱い |

**同じ商品が、悩みの数だけ違う市場を持つ。** リサーチとは「商品を探すこと」ではなく「**売れている商品に、まだ使われていない悩みを見つけること**」。

### 楽天側で売れる商品の条件

| 条件 | 基準 | 理由 |
|---|---|---|
| **レビュー数** | 500件以上 | 社会的証明。発信者の信用を代替する |
| **レビュー評価** | 4.3以上 | 低評価だとクリックされても買われない |
| **価格帯** | **3,000〜6,000円** | 即決できる上限。1万超は比較検討に入り、24時間以内のカート投入率が落ちる |
| 送料 | 無料 | 送料でカート離脱する |
| 画像 | 1枚で違いが分かる | Threadsは画像が主戦場 |
| バリエーション | 色・サイズが複数 | **「他の色は?」がクリック動機になる**（フックの材料） |

> **1商品1個あたり報酬1,000円上限**があるので、料率5%なら20,000円で頭打ち。高額商品を狙う戦略は途中で効かなくなる（`03-規約・法令チェックリスト.md` §1-4）。

## 2. 「需要が確認されているテーマ」の定義

動画の判定基準は「いいね100以上 ＋ 青リンク ＋ PR表記」の3つだけ。**これは必要条件であって十分条件ではない。**

### 追加する2条件

| 条件 | 判定 | なぜ |
|---|---|---|
| **④ 複数アカウントが伸びている** | 同じ商品/テーマで、**3アカウント以上**が100いいね超を取っている | 1人だけが伸びている場合、**その人の属人性**（顔・実績・フォロワー）が原因かもしれない。再現できない |
| **⑤ コメントに質問がある** | 「サイズは?」「◯◯でも使える?」等 | **まだ解決していない需要**が残っている＝自分が入る余地がある。質問ゼロは、完全に満たされているか関心が薄いかのどちらか |

**5条件すべて満たすものだけを商品プールに入れる。**

### 逆に避けるサイン（飽和）

| サイン | 意味 |
|---|---|
| 同じ商品の投稿が検索上位に5件以上 | 飽和。CTRが落ちる |
| いいねは多いがコメントがゼロ | 消費されているだけ。購買意図が薄い |
| 大型アカウント（フォロワー1万超）が主戦場 | 信用勝負になり、新規は勝てない |
| セール期間だけ伸びている | 需要ではなく価格に反応しているだけ |

## 3. 競合投稿から抽出するもの

動画は「商品名」しか持ち帰っていない。**持ち帰るべきは9項目**。

| # | 抽出項目 | 見る場所 | 使い道 |
|---|---|---|---|
| 1 | 商品名・価格帯・ジャンル料率 | リンク先 | 需要と単価の確認 |
| 2 | **1行目の型** | 投稿冒頭 | フックの再現。ここだけで伸びが決まる |
| 3 | **画像の構図** | 添付画像 | 俯瞰／寄り／使用中／Before-After のどれが効いているか |
| 4 | 画像の枚数 | 同上 | 1枚か複数か |
| 5 | **リンク直前のフック文** | セルフリプライ | **CTRの源泉**。動画で唯一教えている実務テク |
| 6 | 投稿時間帯 | 投稿の時刻表示 | 初速の条件 |
| 7 | いいね：コメント比 | 投稿下部 | **コメント比率が高い＝関与が深い＝購買に近い** |
| 8 | **コメント欄の質問内容** | コメント欄 | ★**最も価値が高い**。未解決needs＝次の投稿ネタが無料で手に入る |
| 9 | 発信者のフォロワー数 | プロフィール | 少ないのに伸びている＝**投稿の力で伸びている＝再現できる** |

### 特に9番の使い方

**フォロワー200人で500いいね取っている投稿** > **フォロワー3万人で2,000いいね取っている投稿**

前者は投稿そのものの力で伸びているので**型が再現可能**。後者はフォロワー資産の効果なので真似ても同じ結果にならない。**リサーチではフォロワーの少ないアカウントの伸びた投稿を優先して集める。**

## 4. リサーチシートの雛形

`リサーチ.csv` として運用。1商品1行。

```csv
発見日,商品名,単価,ジャンル,料率,レビュー数,評価,参考投稿URL,発信者フォロワー数,いいね,コメント数,1行目の型,画像構図,リンク前フック,コメントの質問内容,判定
D2,○○ブランケット,3480,ペット,5%,1240,4.5,...,320,512,28,情景型,俯瞰,色展開が最高すぎる,「洗濯機で洗える?」,採用
```

**「コメントの質問内容」の列が投稿ネタのタネになる。** リサーチと投稿ネタ出しを別作業にしない。

## 5. 検索の回し方（実務）

### 5-1. 縦に掘る（同じジャンルで深く）
```
Threads検索 → ジャンル語 → 「人気投稿」タブ
  → 5条件で絞る → シートに記録
```

### 5-2. 横に広げる（隣接ジャンルへ）
伸びている投稿の**発信者のプロフィール**を開き、その人の他の投稿を見る。1人の勝ちアカウントから、**5〜10商品**が一度に取れる。

### 5-3. 逆引き（楽天側から）
楽天ランキング（ジャンル別・デイリー）で上位の商品名をThreadsで検索し、**まだ誰も投稿していない売れ筋**を探す。
- ヒット0件 → 需要はあるがThreadsで未開拓（**当たりの可能性**）
- ヒット多数 → 飽和

### 5-4. 質問から探す（最上流）
コメント欄で拾った質問（「◯◯で使えるやつない?」）を検索語にして、**答えになる商品**を楽天で探す。**需要が先、商品が後**。この順序が本来正しい。

---

## 6. 運用ルール

| 頻度 | やること |
|---|---|
| 毎日 | 5分。1商品を5条件で判定してシートに追加 |
| 週次 | 商品プールを**常時20件以上**に保つ。使い切ると投稿の質が落ちる |
| 月次 | 飽和した商品を除外。ランキング逆引きで新規を補充 |

**リサーチを止めると2週間で在庫が尽きる。** 投稿作業より先にリサーチが止まるのが、この手法で挫折する最大の原因。

---

## 7. この工程が本体である理由

```
需要発見（07）  →  コンテンツ（08）  →  販売（01）  →  計測（06・09）  →  再現（09）
    ↑                                                                    │
    └────────────────── 勝ちパターンから需要を再定義 ──────────────────┘
```

**投稿は需要発見の出力でしかない。** 「投稿文を100個作る」から始めるのは、この図の真ん中から始めているのと同じで、必ず失速する。

そしてこのループ自体は**Threadsにも楽天にも依存していない**。媒体と商材を差し替えれば、そのまま採用媒体でも自社サービスでも回る（→ `10-出口設計とLTV.md`）。
