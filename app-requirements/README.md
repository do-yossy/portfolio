# アプリ企画 要件定義（候補3案・同時進行）

このディレクトリは、「世の中にない、役に立つ、有料化もあり得る、自分たちで作れる」アプリを作るための **要件定義書のたたき台** をまとめたものです。

一本に絞る前に、有力な複数案を "具体的な要件定義" に落として、実物ドキュメントで比較・判断できるようにしています。

## この企画で決めた「良いアプリ」の条件

長い探索の末、次の軸に収束しました。

1. **世に出回っていない**（新規性・ありそうでなかった）
2. **役に立つ**（実用的、できれば感謝される）
3. **有料にする意味がある**（成功報酬は現実的に難しいため、**一回払い or 月額**で成立すること）
4. **自分たちで作れる**（純粋なソフトウェアで、特殊な許認可・物理設備・独自データ連携に依存しない）

> ⚠️ 探索の中で分かった構造的な事実：**「新規性」と「収益性」は対立しやすい**。空いている領域は"儲けにくいから空いている"ことが多く、儲かる領域は"儲かるから既に埋まっている"。だから全条件を100点で満たす案は滅多に出ない。**弱い1軸を設計で底上げする**前提で選ぶ。

## 進め方（推奨）

1. 各要件定義書を読み、「これは違う」と感じた案を削る
2. 残った案について、競合・新規性を **実際の市場でもう一段深く検証**（①制度・給付金発見AIが実は既存だった、という失敗を繰り返さないため）
3. 主役を1つ決め、MVPのプロトタイプ作成へ

## 各要件定義書の共通フォーマット

- 背景・目的
- ターゲットユーザー
- 解決する課題
- 主要機能（MVP）
- やらないこと（スコープ外）
- 非機能要件
- 収益モデル
- 技術構成（作れる根拠）
- 競合・新規性（要検証事項つき）
- リスクと対策
- 成功指標（KPI）
- ロードマップ
