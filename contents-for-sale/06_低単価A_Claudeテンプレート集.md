# Claude Code指示テンプレート集30選

Claude Codeに何を入力すればいいか分からなくて固まってしまう——そんな経験、私も最初は毎日していました。

このテンプレート集は「こう書けばちゃんと動くものを作ってくれる」という言葉の型を30個まとめたものです。そのままコピペして、`[ ]`の部分だけ自分の状況に書き換えて使ってください。

## カテゴリ1: システム作成系（10個）

**テンプレート01: ログイン機能の作成**
用途：メールアドレスとパスワードでログインできる基本的な認証機能を作るとき
```
[アプリ名]にログイン機能を実装してください。

要件：
- メールアドレスとパスワードでログインできること
- パスワードはbcryptでハッシュ化して保存すること
- ログイン成功後はセッションまたはJWTトークンで認証状態を管理すること
- ログイン失敗時は「メールアドレスまたはパスワードが正しくありません」とだけ表示すること（セキュリティのため具体的な原因は教えない）
- ログアウト機能も合わせて実装すること

使用技術は現在のプロジェクトに合わせてください。
既存のコードがあれば確認してから実装してください。
```
💡 使い方のコツ：「現在のプロジェクトに合わせてください」という一文を入れると、Claudeが既存ファイルを確認してから実装してくれます。後から「合わない」と言われるケースが激減します。

**テンプレート03: REST API エンドポイントの作成**
用途：フロントエンドから呼び出すAPIを作るとき
```
以下の仕様でREST APIエンドポイントを作成してください。

リソース名：[テーブル名 / リソース名]
ベースURL：/api/[リソース名の複数形]

実装するエンドポイント：
- GET /api/[リソース名] → 一覧取得（ページネーション対応）
- GET /api/[リソース名]/:id → 1件取得
- POST /api/[リソース名] → 新規作成
- PUT /api/[リソース名]/:id → 更新
- DELETE /api/[リソース名]/:id → 削除

各エンドポイントに以下を含めてください：
- 入力バリデーション
- 適切なHTTPステータスコードのレスポンス
- エラー時のJSONレスポンス形式（{ "error": "メッセージ" }）
- 認証済みユーザーのみアクセス可能にすること

既存の認証ミドルウェアがあれば活用してください。
```
💡 使い方のコツ：エラー時のJSONレスポンス形式を明示することで、フロントエンドとの連携がスムーズになります。後からフォーマットを統一し直す手間が省けます。

```
管理者向けのユーザー管理機能を実装してください。

```

```
フォームの項目：
```

💡 使い方のコツ：最初から権限の種類と名前を決めて伝えると、後から変更する手間が省けます。「あとで追加するかも」という場合も、ロールをテーブルで管理する形にしてもらいましょう。

**テンプレート15: TypeScript型エラーの修正**
用途：TypeScriptの型エラーでビルドが通らないとき
```
TypeScriptの型エラーが出ていてビルドできません。

【エラーメッセージ】
[エラーをここに貼り付け]

【該当コード】
[エラーが出ているコードを貼り付け]

修正にあたって以下の方針でお願いします：
- `any`型は使わない（型安全を保つ）
- 型アサーション（as）は本当に必要な場合のみ使う
- 既存の型定義ファイルがあれば確認してから修正する
- 型エラーの根本原因を解消する（型の誤魔化しはしない）

修正後、なぜその型にする必要があるかの説明もお願いします。
```
💡 使い方のコツ：`any`型の禁止を明示しないと、Claudeが手っ取り早く`any`で解決しようとすることがあります。それでは型エラーを隠しているだけです。

**テンプレート16: 非同期処理のエラー修正**

```

```
💡 使い方のコツ：非同期エラーは「どの処理が非同期なのか」をコードで見せるのが一番です。言葉で説明するより、コードを貼った方が確実に解決します。

## テンプレートをもっと活用するコツ

### コツ1：「確認してから実装してください」を入れる

Claudeは指示通りに作ってくれますが、既存のコードを確認せずに作ることがあります。テンプレートに「既存のコードを確認してから実装してください」という一文を入れるだけで、既存の設計に合った実装をしてくれるようになります。

### コツ2：制約を先に伝える

「〇〇は使わないでください」「△△方式で実装してください」という制約は、最初に伝えてしまいましょう。後から「それは困る」と言っても、大きな修正が必要になることがあります。

### コツ3：段階的に作ってもらう

複雑な機能を一度に全部作ろうとするより、「まず最小限の動くものを作って」→「テストが通ったら機能を追加して」という順番で進める方が、うまくいきます。一度に多くを求めすぎると、どこかにミスが混入しやすくなります。

### コツ4：エラーが出たらそのままコピペする

エラーメッセージは言葉で説明せず、ターミナルに表示された内容をそのままコピペしましょう。「〇〇というエラーが出ました」という要約より、生のエラーメッセージの方がずっと正確に問題を伝えられます。

### コツ5：「なぜそう実装するのか」を聞く習慣をつける

実装してもらったコードの理由が分からないときは「なぜこのやり方にしたか教えてください」と聞いてみましょう。理解が深まるのはもちろん、「実は別のやり方の方が良かった」と気づけることもあります。

### 販売ページ本文

Claude Codeを使い始めたとき、私が一番困ったのは「何を入力すればいいか分からない」という問題でした。

「ログイン機能を作って」と入力しても、何かが足りないせいか動かないコードが出てくる。「エラーが出ました」と書いても、的外れな修正が来る。「あとでやり直し」の繰り返しで、気づけば1時間が溶けていました。

問題は私のプログラミング知識ではなく、「Claudeへの伝え方」でした。

適切な情報を適切な順番で伝えるだけで、Claude Codeは驚くほど正確に動くものを作ってくれます。ただ、その「伝え方の型」を見つけるのに、私は何十時間もの試行錯誤が必要でした。

このコンテンツはその試行錯誤の成果です。

システム作成・エラー修正・機能追加・デプロイという4つのカテゴリに分けた30個のテンプレートは、全てそのままコピペして使えます。`[ ]`の部分を自分の状況に書き換えるだけです。

購入後にすぐ変わること——「今日はどんな指示を書けばいいんだろう」と悩む時間がなくなります。テンプレートを開いて、当てはまるものを選んで、貼り付ける。それだけで、Claude Codeが的確に動き始めます。

プログラミングの知識よりも「伝え方の知識」が大切だということに気づいたとき、Claude Codeとの関係は変わりました。同じ気づきを、このテンプレート集でお届けします。
