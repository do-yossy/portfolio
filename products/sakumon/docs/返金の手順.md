# 返金の手順(運営用)

代表決定(2026-11-12):お支払い済みの料金は、日割りの分を含めて返金しない。**ただし、当社の責めで連続7日以上サクモンを使えなかった場合は、直近にお支払いいただいた1か月分の料金を返金する。**
利用者向けの文言は、`src/company.js`(`refundPolicy`)と、利用規約の第3条にある。

## 「当社の責め」の範囲(担当の案。代表の最終確認待ち)

2026-11-13 に代表から「範囲と手順(問い合わせ→確認→Stripeで返金)で」と指示があり、範囲の中身は担当(Claude)が下の案にした。**外部サービスの障害の扱いなど、細部は代表が決める。** 変えるときは、この表と、利用規約の第3条(`src/legal.js`)をそろえて直し、監査役を通す。

| 返金の対象になる | 返金の対象にならない |
|---|---|
| サクモンのプログラムの不具合 | 利用者の端末・回線・ブラウザの事情(Cookie の削除、古いブラウザなど) |
| 当社の設定や運用の誤り(誤ったデプロイ、公開スイッチの誤り、契約状態の記録の誤りで使えなくなった、など) | 天災・停電・当社が対処できない広い範囲の通信障害などの不可抗力 |
| 当社が行った保守・変更が原因の停止 | 利用者が規約に違反して利用を停止された場合 |

- **グレーのもの**:Cloudflare・Stripe など、外部サービスの障害。上の表では、「当社が対処できない広い範囲の障害」なら対象外、サクモン側の設定の誤りが重なっていれば対象、と読む。迷ったときは、**利用者に有利な側**で判断する(個別に代表へ相談)。
- 「連続して7日以上」は、日付で数える。日中の数時間の停止は、数に入れない(7日続くことは、まずない)。

## 手順

1. **受付**:お問い合わせフォーム(`https://www.social-quality.com/お問い合わせ.html`)で、利用者から連絡が来る。お申し込みのメールアドレスと、使えなかった期間を、書いてもらう。足りなければ、返信で聞く。
2. **本人の確認**:申し込みのメールアドレスが、Stripe の顧客のメールアドレスと一致するか確認する。一致しなければ、返金しない(別の人の契約かもしれない)。
3. **事実の確認**:
   - サクモンが実際に止まっていたか。Cloudflare のダッシュボード(Workers & Pages → sakumon → Metrics / Logs)と、Cloudflare の障害情報で、期間を確認する。
   - 原因が上の表の「当社の責め」に当たるか判断する。
   - 利用者の契約が、その期間、有効だったか(`members` の `status`)。
4. **判断を記録**:誰が・いつ・どの期間・何を根拠に・返金する/しない、を運営メモに残す。**利用者の氏名・メール以外の個人情報は、書かない。**
5. **返金する場合**(代表の操作。Stripe の本番の操作なので、Claude は代行しない):
   1. Stripe ダッシュボード(本番モード)にログインする。
   2. 「顧客」から、メールアドレスで検索して、該当の顧客を開く。
   3. 「支払い」の一覧から、**直近の請求**(1か月分の料金)を開く。
   4. 右上の「…」(または「返金」ボタン)→「支払いを返金」。金額は、**その月の料金の全額**にする。理由は「その他」にして、メモに運営メモの日付を書く。
   5. 返金を確定する。カードへの反映は、カード会社により数日〜数週間かかる、と伝える。
   - 画面の表示は、Stripe の更新で変わることがある。
6. **返信**:返金した/しない(しない場合は理由)を、お問い合わせへの返信で伝える。返金した場合は、金額と、カードへの反映に時間がかかる旨を書く。
7. **契約は自動で続く**:返金しても、契約は解約されない。利用者が続けたくない場合は、会員ページの「解約・支払い方法の変更・請求書」から解約してもらう(代わりに解約を勧めない)。

## 注意

- 二重に契約してしまった場合の返金は、「二重請求の防止」(README の「入れなくなったお客様の対応」)で扱う。この手順は、使えなかった場合の返金のためのもの。
- Stripe の決済手数料が、返金で戻るかどうかは、**確認していない**。返金の損益は、Stripe の料金ページで確認してください。
- 返金の件数・金額は、集計して代表に報告する(件数が増える場合は、原因の対策を先に考える)。
