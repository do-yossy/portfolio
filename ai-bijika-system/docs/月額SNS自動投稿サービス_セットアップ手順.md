# 月額SNS自動投稿サービス セットアップ手順

月額1,000円（税込）のSNS自動投稿サービス（`/service`）を、販売できる状態にするための手順です。コードは完成していますが、**決済アカウントとSNSの開発者アプリは、運営者ご自身で作る必要があります**（私たちが代わりに作ることはできません）。

## 1. 自動化されていること

| 流れ | 自動化の内容 |
|---|---|
| 販売ページ | `/service` に、料金・自動更新・解約・返金・制限を表示 |
| 申込み | アカウント作成 → 最終確認画面（金額・自動更新・解約方法・返金なし・同意）→ Stripeの決済ページ |
| 契約の開始 | Stripeから届くWebhookで、自動的に契約中になる（人の作業は不要） |
| 利用 | SNS連携（OAuth）、予約投稿、予約の実行、再試行 |
| 更新・解約 | Stripeが毎月自動で請求。マイページの「解約する」で次回更新を停止 |
| 支払い失敗 | 契約が「お支払いの確認が必要」になり、投稿が止まる（Stripe側の督促メールの設定は下記） |
| 投稿の作成 | 6つのSNS（Threads・X・Instagram・TikTok・Facebookページ・YouTube。Xは当面使わない方針）。テキスト・画像（複数枚）・動画・ツリー、SNSごとの本文、下書き、カレンダー |
| AI | 投稿文・画像・動画の生成、毎日の自動運用（下書きに入れる／完全自動） |
| 外部からの操作 | REST API（`/api/v1`）とAPIキー、MCP（`/mcp`。OAuthでAPIキーなしで接続）、Claude Code用のスキル（`/service/docs/skill.md`） |
| 無料トライアル | `SERVICE_TRIAL_DAYS` を設定すると、初めての人だけ無料期間つきで申し込める（カード登録必須・期間後に自動課金） |

## 2. 運営者が行う作業

### 2-0. 各SNSのキーの作成と審査の申請（リンク集）

キー（アプリID・シークレットなど）の作成も、審査の申請も、各社の管理画面で行います。「説明」のリンクは、各社の公式の解説ページです。管理画面はログインが必要です。リンクは2026年10月15日に開けることを確かめました（管理画面はログインの画面に移ります）。**ページの場所は各社が変えることがあります。** 開けないときは、管理画面のトップから同じ名前のメニューを探してください。審査の申請の場所（メニューやボタンの名前）は、ログイン後の画面では確かめていません。各社の公式の説明ページの記載に合わせています。

Xは、使わない方針（APIが有料のため。お試し手順の冒頭を参照）なので載せていません。下の 2-3 は、将来Xを使う場合の手順です。

### 2-1. Stripe（決済）

1. Stripeのアカウントを作成し、事業者情報の確認を済ませる（本番の決済には必要）。
2. 商品と価格を作る：商品名「ミチシルベ 自動投稿」、価格 **月額 1,000円（JPY、毎月の継続課金）**。作成した価格のID（`price_...`）を控える。
3. Webhookを登録する：エンドポイントURLは `https://（公開URL）/api/stripe/webhook`。送信するイベントは次の6つ。
   - `checkout.session.completed`
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `invoice.paid`
   - `invoice.payment_failed`

   登録後に表示される「署名シークレット」（`whsec_...`）を控える。
4. カスタマーポータルを有効にする（支払い方法の変更・請求書の確認に使う）：Stripeの設定 → 請求 → カスタマーポータル。**ポータルから解約できるようにする場合は、「請求期間の終了時に解約」に設定してください**（即時の解約にすると、期間の途中でSNSの連携などが消え、規約・画面の説明と合わなくなります）。
5. 支払い失敗の督促メール・領収書メールを送る設定にする：Stripeの設定 → 請求 → サブスクリプションとメール。**無料トライアル（`SERVICE_TRIAL_DAYS`）を使う場合は、「トライアル終了前のお知らせメール」も送る設定にしてください**（カード会社の規則で求められる場合があります。最新の条件はStripeの公式で確認してください）。
6. **Stripeの価格（月額）と、環境変数 `SERVICE_PRICE_JPY`（画面に表示する金額。既定1000）を必ず一致させてください。** 違うと、画面の表示と請求額が食い違います。規約（第3条）と特商法表記の「月額1,000円」は文書に直接書いているので、価格を変えるときは文書も直してください。
7. **まず「テストモード」で動作確認する**（テスト用のカード番号 `4242 4242 4242 4242`）。問題なければ、本番のキーに切り替える。

### 2-2. Threads（Metaの開発者アプリ）

1. Meta for Developers でアプリを作り、「Threads API」のユースケースを追加する。
2. 「有効なOAuthリダイレクトURI」に `https://（公開URL）/service/oauth/callback/threads` を登録する。
3. 権限は `threads_basic`・`threads_content_publish`・`threads_manage_replies`（`threads_manage_replies` はツリー＝連投に必要です）。**この権限を追加する前に連携した利用者は、ツリーを使うには連携のやり直しが必要です**（1件目は投稿され、2件目以降が失敗します）。
   - 本物のThreadsで最初に確かめること（公式に書かれていない、または確かめていない点）：
     - テキストだけの投稿のコンテナで、状態（`status`）が返るか。返らない場合、このサービスは待たずに公開へ進みます。
     - 異体字セレクタの付かない記号（❤ © ™ など）を、Threadsが絵文字としてバイト数で数えるか。このサービスは絵文字として数えています（画面も同じ）。
   - 公開の応答が届かなかった場合（通信エラーなど）、このサービスは公式の案内どおりコンテナの状態を確かめ、公開済みなら投稿済みにします。公開済みと確かめられなければ、**同じコンテナで公開をやり直さず**（同じコンテナを2回公開できるかが公式に書かれていないため）、利用者に投稿されたかの確認をお願いします。
4. **自分以外の利用者に公開するには、Metaのアプリレビュー（審査）と、アプリを「ライブ」にすることが必要**です。書類（プライバシーポリシーのURLなど）が求められます。審査に通るまでは、アプリの管理者・テスターだけが連携できます。
5. アプリIDとアプリシークレットを控える。

### 2-3. X（X Developer Portal）（当面は使わない）

1. プロジェクトとアプリを作る。「ユーザー認証の設定」で、**OAuth 2.0・種類は「Webアプリ・機密クライアント」**にする。
2. コールバックURLに `https://（公開URL）/service/oauth/callback/x` を登録する。
3. 権限は「読み取りと書き込み」。スコープは `tweet.read tweet.write users.read offline.access media.write`（`media.write` は画像・動画の添付に必要です）。**このスコープを追加する前に連携した利用者は、画像・動画を付けるには連携のやり直しが必要です。マイページやメールで告知してください。**
   - 画像・動画は、Xのv2のメディアアップロード（画像は `POST /2/media/upload`、動画は `initialize`／`append`／`finalize` の分割アップロード）で送ります。**エンドポイントの細部は、本物のAPIでは未検証です**（モックのテストのみ）。
4. **Xの投稿APIには、利用プランごとの投稿数の制限と費用があります。** 契約するプランの条件（月間の投稿上限、費用）を、公式の最新情報で必ず確認してください。1,000円の月額で採算が合うかも、ここで決まります。利用者1人あたりのXへの投稿は、`X_MONTHLY_LIMIT`（既定30件／月。ツリーは1件ずつ数えます）で制限しています。費用に合わせて調整してください。
5. クライアントIDとクライアントシークレットを控える。

### 2-3-1. Instagram（Metaの開発者アプリ：「Instagram APIとInstagram ログイン」）

1. Meta for Developers のアプリに、「Instagram」製品（Instagram APIとInstagram ログイン）を追加する（Threadsとは別のアプリとして作成する想定です。同じアプリで両方を使えるかは、未確認です）。
2. 「有効なOAuthリダイレクトURI」に `https://（公開URL）/service/oauth/callback/instagram` を登録する。
3. 権限（スコープ）は `instagram_business_basic` と `instagram_business_content_publish`。
4. **自分以外の利用者に公開するには、Metaのアプリレビュー（`instagram_business_content_publish` の承認）と、アプリを「ライブ」にすることが必要**です。ビジネス確認などが求められる場合があります。
5. 利用者のInstagramは、**プロアカウント（ビジネス／クリエイター）**である必要があります（個人アカウントには投稿できません）。
6. 投稿できるもの：画像（**JPEGのみ**）とリール動画（MP4・MOV）。テキストのみの投稿はできません。画像・動画は、公開URL（`https://（公開URL）/media/...`）からMeta側が取得します。
7. アプリIDとアプリシークレットを控える。

### 2-3-2. TikTok（TikTok for Developers）

1. アプリを作成し、「Login Kit」と「Content Posting API」の製品を追加する。スコープは `user.info.basic` と `video.publish`（写真の投稿に同じスコープで足りるかは、公式で確認してください）。
2. 「リダイレクトURI」に `https://（公開URL）/service/oauth/callback/tiktok` を登録する。
3. TikTokの審査は2つあります。**アプリの審査**（アプリの管理画面の「Submit for review」）と、**投稿の監査（Audit）**（Content Posting API の監査の申請。2-0 のリンク集）です。段階ごとの制限は次のとおりです（公式の「Add a Sandbox」と「Content Sharing Guidelines」による）。
   - **アプリの審査に通るまで**：サンドボックスで、ターゲットユーザー（テスター）に追加したアカウント（自分が持つアカウントを10個まで）しか使えません。
   - **アプリの審査に通ったあと、投稿の監査に通るまで**：テスター以外の人も使えますが、**投稿は公開範囲「自分のみ」だけ**、投稿できるのは**24時間で5人まで**、**投稿するアカウントはすべて非公開（プライベート）**にしておく必要があります。
   - 一般の利用者に公開範囲を選ばせるには、投稿の監査が必須です。監査で何を出すか（デモ動画など）の詳しい手順は、公式の公開ページでは確かめられていません（第三者の解説では、デモ動画などが求められるとされています）。TikTokのガイドラインに沿った画面（公開範囲の選択、コメント・デュエット・ステッチの可否、利用者への表示など）が必要です。投稿フォームのTikTokの設定欄は、TikTokのガイドラインを意識して、公開範囲の選択肢と、コメント等の可否をTikTokから取得して反映し、商用コンテンツの開示、動画のプレビュー、音楽使用の確認の表示を入れています。ただし、**ガイドラインを満たしているかは、審査を通すまで確認できておらず、審査で追加の修正を求められる可能性があります**。
   - 投稿の監査の前は、投稿に使うすべてのTikTokアカウント（テスターも、それ以外の利用者も）を**非公開（プライベート）アカウント**にしておく必要があります（公開アカウントだと、TikTokが投稿を拒否します）。
   - **投稿の監査（Audit）に通ったら**、環境変数 `TIKTOK_AUDITED=true` を設定します（アプリの審査に通っただけでは設定しないでください。設定すると、利用者が「全員に公開」などを選べるようになりますが、TikTokが投稿を拒否します）。設定するまでは、投稿フォームで選べる公開範囲は「自分のみ」だけです（TikTokから取得した選択肢を「自分のみ」に絞って表示し、ほかの値は保存のときにも断ります）。
4. 動画はファイルアップロード方式で送るため、URLの所有確認は不要です。
5. **写真の投稿（JPEG・35枚まで）は、TikTokが当サービスの公開URL（`https://（公開URL）/media/...`）から画像を取得する方式（`PULL_FROM_URL`）です。TikTokの開発者ポータルで、公開URLのドメイン（またはURLの先頭部分）の所有確認が必要です。** 確認していないと、写真の投稿は失敗します。
   - 会社ドメインのサブドメイン（例：`post.social-quality.com`）で運用する場合、所有確認は `social-quality.com` のDNSにTikTokが指定するTXTレコードを追加して行います（費用はかかりません）。
6. クライアントキーとクライアントシークレットを控える。

### 2-3-4. Facebookページ（Metaの開発者アプリ：Facebookログイン）

1. Meta for Developers でアプリを作り（ビジネスタイプ）、「Facebook Login for Business」を追加して、「ユーザーアクセストークン」の設定を作る（ビジネスタイプのアプリでは、通常の「Facebookログイン」は使えません）。今のコードは `scope` と `auth_type=rerequest` で権限を求めています。Facebook Login for Business は `config_id` を渡す方式が基本のため、`scope` で動くかは未確認です。うまくいかない場合は、`config_id` を渡す方式に直します。`business_management` を全員に求めると、アプリレビューで審査される権限が増えます（ビジネスポートフォリオのページを使わないなら、外すことも検討してください）。
2. 「有効なOAuthリダイレクトURI」に `https://（公開URL）/service/oauth/callback/facebook` を登録する。
3. 権限は `pages_show_list`・`pages_manage_posts`・`pages_read_engagement`・`business_management`（ビジネスポートフォリオにひも付いたページは、`business_management` が無いと一覧に出てきません）。ユースケースにも同じ権限を追加します。**一般の利用者に公開するには、アプリレビューとビジネス確認が必要**です。
4. 連携のとき、投稿に必要な権限が許可されたかを確認し、足りなければ連携を止めます。投稿できる（CREATE_CONTENT の作業ができる）ページが**1つだけ**のとき、そのページが投稿先になります。2つ以上あるときは連携を止め、Facebookの画面でページを1つだけ選び直すよう案内します（サービス内でページを選ぶ画面は、まだありません）。個人のタイムラインには投稿できません。
5. 投稿できるもの：テキスト、画像（10枚まで）、動画1本。本文の上限（63,206文字）と画像の枚数（10枚）は、公式に明記が見つからなかった目安です。本文なしの画像の投稿と、動画の `file_url` 方式での投稿は、テスターのページで動くかを確かめてください。アプリIDとアプリシークレットを控える。
6. Graph APIは `v22.0` を使っています（2027年5月20日まで使えます）。それまでに新しい版に上げて、動作を確かめてください。

### 2-3-5. YouTube（Google Cloud）

1. Google Cloud でプロジェクトを作り、「YouTube Data API v3」を有効にする。
2. 「OAuth同意画面」を設定し、OAuthクライアント（ウェブアプリ）を作る。承認済みのリダイレクトURIに `https://（公開URL）/service/oauth/callback/youtube` を登録する。スコープは `youtube.upload` と `youtube.readonly`。
3. **一般公開には、Googleによるアプリの確認（OAuthの審査）が必要**です。プライバシーポリシーには、Googleのユーザーデータの取り扱い（Limited Use）の記載を入れています（4-2）。
4. **重要：監査（YouTube API Services の Audit）を通っていないプロジェクトからアップロードした動画が「非公開」に制限されるかは、公式の記述が食い違っています**（APIの説明では制限されない、YouTubeヘルプでは非公開に固定される）。テスターのアカウントで「公開」を1本試し、YouTube Studioで確認してください。一般の利用者に公開する前に、監査を申請してください。
5. **動画のアップロード（`videos.insert`）には専用の割り当てがあり、初期値はプロジェクト全体で1日100回です**（太平洋時間の0時にリセット）。サービスでは `YOUTUBE_DAILY_LIMIT`（サービス全体。既定90件）と `YOUTUBE_PER_USER_DAILY`（利用者ごと。既定5件）で、1日の予約と実際のアップロードの件数を制限しています（1人で全体の枠を使い切らないように）。実際の割り当ての値は、Google Cloud コンソールの「割り当て」の画面で確かめてください（公式のページには、古い「1回1,600単位」の記述が残っている箇所があります）。上限を超える予約は受け付けず、送る時点で上限に達していれば、YouTubeの日付が変わった後に回します。利用者が増える場合は、監査と割り当ての増加を申請してください。
6. **OAuth同意画面が「テスト中」の間は、更新用のトークンが7日で切れます**（テストユーザーは100人まで）。テスト中は、連携から7日以内に実行される予約で試してください。7日を過ぎると「連携のやり直しが必要」になります。
7. 本文の1行目がタイトル（100文字まで）になり、収まる場合は「#Shorts」を付けて投稿します（3分以内で、正方形か縦長の動画がショートとして扱われます）。説明（本文全体）は5,000バイト（日本語でおよそ1,600文字）まで、半角の `<` `>` は全角に置き換えて送ります。連携のとき、動画のアップロードの権限（`youtube.upload`）が許可されたかを確認します。
8. 開発者ポリシーにより、プライバシーポリシーに「YouTube API Services を利用している」ことと、Googleのプライバシーポリシーへのリンクを、利用規約にYouTube利用規約へのリンクと同意の文を入れています。クライアントIDとシークレットを控える。

### 2-3-6. AIによる生成（任意）

キーを設定した機能だけが有効になります（未設定なら、画面にAIのボタンが出ません）。

| 機能 | 環境変数 | 既定のモデル（変更可） |
|---|---|---|
| 投稿文 | `ANTHROPIC_API_KEY` | `AI_TEXT_MODEL`（既定 `claude-haiku-5-5`） |
| 画像（JPEG） | `OPENAI_API_KEY` | `AI_IMAGE_MODEL`（既定 `gpt-image-1`） |
| 動画 | `GEMINI_API_KEY` と `AI_DAILY_VIDEO`（1以上） | `AI_VIDEO_MODEL`（既定 `veo-3.0-generate-001`。数分かかる非同期の生成）。**既定では無効**です |

- **AIの利用料は、生成のたびに運営者に請求されます。** 1人あたりの上限は、1日（`AI_DAILY_TEXT` 既定30回、`AI_DAILY_IMAGE` 既定5回、`AI_DAILY_VIDEO` 既定0回＝無効）と1か月（`AI_MONTHLY_TEXT` 既定300回、`AI_MONTHLY_IMAGE` 既定60回、`AI_MONTHLY_VIDEO` 既定10回）の両方で決まります。各社の最新の料金を確認したうえで、月額1,000円で採算が合うように決めてください。上限は、自動運用で作る分も含みます。0にすると、その生成は画面に出なくなります。
- **オーナーの判断（2026年10月14日）により、当面は文章と画像だけを提供し、動画の生成は提供しません**（`GEMINI_API_KEY` と `AI_DAILY_VIDEO` は設定しないでください）。利用者は、ご自身のAIで作った動画をアップロードして投稿できます。動画の生成を提供する場合は、規約（第1条・第7条・第8条）とプライバシーポリシー（4の2項・4-3）の改定が必要です。
- **動画の生成は、1本あたりの費用が文章・画像より大幅に高くなりやすく、月額1,000円の中で多く使うと赤字になるおそれがあります**（金額は Google の最新の料金表で確認してください）。動画を有効にする場合は、`AI_DAILY_VIDEO` と `AI_MONTHLY_VIDEO` を小さな値から始めてください。動画を多く使いたい利用者向けには、別料金のプランを用意することも検討してください。
- 自動運用は、1日に3回までの時刻・テーマの順番・作るもの（文章／画像／動画）を設定できます。動画は、できあがった時点（数分後）で下書き・予約を作ります。TikTokは、投稿ごとに本人の確認が必要なため、自動運用の対象外です（「投稿を作る」画面でAIを使って作り、確認してから投稿します）。
- AIの生成は、契約中（またはテスト利用中）の利用者だけが使えます（画面・API・MCP・自動運用のどこから呼んでも、同じ確認をします）。
- **AIの各社APIとの接続は未検証です**（モックのテストのみ）。とくに動画（Veo）のエンドポイントと結果の形式は、公式の最新ドキュメントで確認が必要です。
- 「自動運用」の完全自動は、AIが作った内容を利用者の確認なしで投稿します。画面と規約で、利用者の同意（チェック）を必須にしています。

### 2-3-7. AIアシスタント（MCP）・API

- 追加の設定は不要です（`SERVICE_BASE_URL` が正しく設定されていれば動きます）。接続先URLは `https://（公開URL）/mcp`。OAuth（クライアントの動的登録・PKCE）で、利用者はログインと「許可する」だけで接続できます。
- **ClaudeやChatGPTの実物の接続画面での動作は未検証です**（OAuthの流れはテストで確認済み）。公開前に、実際のアプリで接続を確認してください。
- URLからの取り込み（`import_media_from_url`）は、社内・ローカルのアドレスへの接続を拒否する対策を入れています。

### 2-3-8. 画像・動画の保存容量

- アップロード・取り込み・AIで作ったファイルは、サーバーのディスク（Fly.ioのボリューム）の `media/` に保存します。画像は8MB、動画は100MBまで、利用者1人あたり合計300MBまでです。予約・下書きに使っているファイルは、その投稿が終わるか取り消されるまで保存し（下書きに使っている間は、下書きを削除するまで保存）、投稿が終わってから2日後以降に自動で削除します。どの投稿にも使わなかったファイル（AIで作ったものを含む）は、作成から1日後以降に自動で削除します。
- 現在のボリュームは1GBで、データベースと共用です。利用者が増える場合は、容量を増やしてください（`fly volumes extend`）。
- **`/media/...` のURLは、ログインなしで取得できます**（Instagram・Threadsなどが取得するため）。推測できない長いURLですが、URLを知っている人は見られます。

### 2-4. 環境変数（Fly.io のシークレット）

`.env.example` の「月額SNS自動投稿サービス」の部分を参照。本番では、次のようにシークレットを登録します（値は控えたもの）。

```
fly secrets set -a sq-ai-bijika \
  SERVICE_BASE_URL=https://（公開URL） SERVICE_CONTACT_EMAIL=（問い合わせ用のメールアドレス） \
  STRIPE_SECRET_KEY=sk_live_... STRIPE_WEBHOOK_SECRET=whsec_... STRIPE_PRICE_ID=price_... \
  SNS_TOKEN_KEY=$(openssl rand -hex 32) APP_SECRET=$(openssl rand -hex 32) \
  THREADS_APP_ID=... THREADS_APP_SECRET=... \
  INSTAGRAM_APP_ID=... INSTAGRAM_APP_SECRET=... \
  TIKTOK_CLIENT_KEY=... TIKTOK_CLIENT_SECRET=... \
  FACEBOOK_APP_ID=... FACEBOOK_APP_SECRET=... \
  GOOGLE_CLIENT_ID=... GOOGLE_CLIENT_SECRET=...
# Xは使わない方針のため、X_CLIENT_ID・X_CLIENT_SECRET は登録しない。登録しなければ、Xは画面（販売ページ・申込み・マイページ・投稿フォーム）に出ない。
# 利用規約・特商法表記・プライバシーポリシーにはXの名前が残る（規約と特商法は「運営者が提供を始めたもの」という書き方なので、そのままでも食い違わない。プライバシーポリシーの X Corp. は、使わない間は消すかどうかを検討する）。将来Xを使う場合だけ足す（2-3）
# 任意：AI（使うものだけ）・無料トライアル
fly secrets set -a sq-ai-bijika ANTHROPIC_API_KEY=... OPENAI_API_KEY=... SERVICE_TRIAL_DAYS=7
```

- `SERVICE_TRIAL_DAYS`：無料期間の日数（1〜30。未設定なら無料期間なし）。初めて申し込む人だけが対象で、Stripeの決済ページでカードの登録が必要、期間が終わると自動で課金されます。最終確認画面に、無料期間・自動課金・解約の期限を自動で表示します。**規約・特商法表記は無料期間ありの内容にも対応していますが、実施する前に運営者が内容を確認してください。**
- `APP_SECRET` は、画面の操作の確認用（CSRF）の鍵です。必ず設定してください（未設定だと再起動のたびに変わり、開いていた画面の操作が失敗します）。

- `SNS_TOKEN_KEY` は、SNSのトークンを暗号化する鍵です。**一度決めたら変更しないでください**（変更すると、連携済みのアカウントがすべて使えなくなります）。
- 各SNSのキーが未設定なら、そのSNSの連携ボタンは「準備中」と表示されます。
- **販売の開始は、運営者が `SERVICE_OPEN=true` を設定したときだけ**です。次の条件がすべてそろわないと、販売ページは「準備中」の表示で、申込みはできません（誤って公開しても、壊れた状態で販売されません）。
  - Stripeの3つ（`STRIPE_SECRET_KEY`・`STRIPE_WEBHOOK_SECRET`・`STRIPE_PRICE_ID`）と `SERVICE_BASE_URL`
  - `SERVICE_CONTACT_EMAIL`（特商法表記とプライバシーポリシーの連絡先に、自動で表示されます）
  - `SNS_TOKEN_KEY` と、6つのSNSのうち1つ以上のキー
- **`SERVICE_OPEN=true` は、使うSNSの審査・設定が終わり、テストモードで通しの動作確認が済んだあとに設定してください。** 審査が終わる前に開くと、契約したのに連携できない利用者が出ます。

## 4. 運用上の注意と、今の制限

- **パスワードを忘れた場合**：メール送信の仕組みがないため、自動の再設定はできません。お問い合わせ（`/contact`）で対応する運用になります。必要ならメール送信（Resend等）を追加できます。
- **ログイン状態**：セッションはメモリ上のため、サーバーの再起動（デプロイ）のたびにログアウトされます（購入済みの契約には影響しません）。
- **スケジューラ**：同じプロセスの中で30秒ごとに予約を確認します。**サーバーは1台のまま**にしてください（複数台にすると、同じ予約を二重に確認する可能性があります。二重投稿は防いでいますが、構成は1台を前提にしています）。
- **本物のAPIとの接続は、すべて未検証です**（Stripe・6つのSNS・AIの各社。テストはすべてモック）。各社の審査（Metaのアプリレビュー、TikTokのアプリの審査と投稿の監査（Audit）、Googleの確認とYouTubeの監査）を通る前は、一般の利用者には提供できません。TikTokは、投稿の監査（Audit）を通る前は「自分のみ」に限られます。YouTubeは、監査前は「非公開」に限られる場合があります（公式の記述が食い違っているため、テストで確認してください）。
- **ポストメッシュと比べて、まだ無いもの**：チームでの共同運用（複数人で1つのアカウントを使う機能）、Facebookで投稿するページの選択、投稿済みの内容の編集。
- **Xの利用条件**：Xのプランや規約の変更で、投稿できなくなる可能性があります。
- **SNS各社の規約**：投稿できるのは、利用者本人が作成・予約した内容だけです。いいね・フォロー・コメントなどの自動操作は、機能として入れていません（各SNSの規約でスパムと判断されるリスクが高いため）。
- **運営者向けの画面**：`/admin/service`（管理者パスワードでログイン）で、契約の状況と予約の件数を確認できます。請求の詳細はStripeのダッシュボードで確認します。
