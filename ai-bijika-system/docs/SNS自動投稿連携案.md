# SNS自動投稿連携案：ポストメッシュAPIを使った複数SNSへの投稿・予約配信

## 背景

「SNSの運用を自動化できる仕組みを作れないか」という依頼を受けた。自動化の範囲について確認したところ、「投稿文・画像などコンテンツ作成の自動化」「作った投稿の予約・自動配信」「いいね・フォロー・コメント返信などの自動化」「他社の投稿・反響の分析やモニタリング」の4つが候補として挙がった。続けて「既存のSNSと連携できるように」という指示と、連携先として[ポストメッシュ](https://post-mesh.com/)（複数SNSへのクロスポスト・予約投稿サービス）のURLが共有された。

当初は運営者専用の社内ツール（`/admin/sns`、運営者のポストメッシュAPIキーを環境変数で設定）として実装したが、その後「ポストメッシュへの登録はこのツールを使う人それぞれが行いAPIキーもご自身で登録してもらう」という指示を受け、**購入者向けの有料ツール**（`/tools/jidoutoukou`）に作り直した。ポストメッシュへの登録・SNSアカウントの連携・APIキーの発行は、購入者自身がそれぞれ行う前提で、運営者側では一切管理しない。続けて「SNS自動投稿ツールと集客ツールをビジネス初心者とMLMでパートナー募集したい方に販売するためのアプローチテキストと商品を作って」という指示を受け、商品化・出品文章・アプローチ文面の作成に進んだ（`docs/TipsSNS自動投稿ツール案.md`・`docs/SNS自動投稿ツールアプローチ文面案.md`参照）。

想定読者は「一般のMLMやビジネス初心者」で、目的は「この方々にミチシルベを買ってもらうため」と確認している。

## 採用した範囲と見送った範囲

4つの候補のうち、実際に実装したのは「コンテンツ作成（AIでの下書き生成）」と「投稿の作成・予約配信」の2つ。「エンゲージメント自動化（いいね・フォロー・コメント返信）」は実装していない。

- SNS各社の利用規約は、自動化されたいいね・フォロー・コメントを、スパム的な行為として禁止または厳しく制限していることが多い。見ず知らずの相手に対してこれを行うと、規約違反としてアカウント停止につながるリスクが高い
- これは、本リポジトリ`CLAUDE.md`の制約「プラットフォームの自動巡回・自動応募は規約違反のため実装しない（求人媒体について）」と全く同じ理由である。対象が求人媒体からSNSに変わっても、この判断基準は変えるべきではないと判断した
- 実は、SNS運用の効率化・自動化の方針自体は本件が初めてではなく、`docs/販売手法案_チャネル別パターン.md`の「B. SNS発信型」内で既に整理されている：「効率化してよい範囲」として下書きのAI作成・公式の予約投稿機能・投稿前の人による確認（無人での自動公開はしない）を挙げ、「避けるべき範囲」として自動いいね・自動フォロー・自動コメント・自動DM等のエンゲージメント操作を明記している（reviewer・監査役審査済み、`審査結果_2026-09-29.md`等参照）。本書の採用・見送りの判断は、この既存方針をそのまま踏襲したものであり、新しい基準を作ったわけではない
- 実務上の裏付けとして、連携先に指定されたポストメッシュ自体も、いいね・フォロー等のエンゲージメント自動化機能を提供していない（投稿の作成・予約のみ）。今回の実装でこの機能を作らなかったことで、機能的な制約が生じることはない
- 「他社の投稿・反響の分析やモニタリング」（インサイト取得）は、ポストメッシュのAPIには存在するが、上位プラン（サブスクリプション）が必要な機能のため、今回は実装を見送った。将来的に必要になった場合は`lib/postmesh.js`に`getInsights`系の関数を追加する形で拡張できる

## 設計方針

- **SNSアカウントの連携（OAuth）自体は実装しない**：各SNSプラットフォーム（X・Threads・Instagram・TikTok・YouTube・Facebook）ごとに開発者アプリの登録・審査が必要なOAuth連携を自前で実装するのは大掛かりであり、依存ゼロ主義（`node:http`のみで書く方針）とも相性が悪い。ポストメッシュが「連携はポストメッシュのダッシュボードで行い、連携済みアカウントへの投稿はAPIで行う」という形で既にこの問題を解決しているため、自前でのOAuth実装を避け、ポストメッシュのAPIを中継する設計にした
- **`lib/postmesh.js`は`lib/aiproxy.js`と同じ設計**：Node標準の`https`モジュールのみを使い、npm依存を増やしていない。APIキーは呼び出しごとに受け取るだけで、ファイル・DB・ログのいずれにも保存しない
- **購入者ごとのパスワード制有料ツール（`/tools/jidoutoukou`）にした理由**：当初は運営者専用の社内ツールとして実装したが、「このツールを使う人それぞれがポストメッシュに登録しAPIキーも自分で用意する」という指示を受け、`/tools/shukyaku`・`/tools/kanyu`と全く同じ設計（`makeToolGate()`による共有パスワード認証、購入者自身のAPIキーを画面から毎回受け取るだけで保存しない）に作り直した。ポストメッシュのAPIキーも、AIプロバイダのAPIキーと同じ扱い（ブラウザのlocalStorageにのみ保存、サーバーには中継のためだけに送られDB・ログには残らない）にしている
- **投稿データをこのアプリ側に保存しない理由**：ポストメッシュ自身が投稿一覧・ステータスを保持しており（`GET /posts`）、こちら側でも同じデータを保存すると二重管理になり、状態がずれるリスクがある。「直近の投稿」一覧は、毎回ポストメッシュへ問い合わせて表示する設計にした
- **AIでの下書き生成を含めた理由**：「コンテンツ作成の自動化」という要望に応えるため、投稿本文をAIに下書きさせる補助機能を追加した。プロンプトには、断定的な収入表現を使わないこと・実在しない実績やお客様の声を含めないことを明示的に指示している（`CLAUDE.md`の絶対ルールに対応）。生成された文章は下書きであり、購入者自身が内容を確認してから投稿する運用を前提にしている

## 前提・確認事項

- ポストメッシュは月額2,200円（年払いの場合2,000円）の有料サービス（7日間の無料トライアルあり）。本ツールを使うには、**購入者自身**がポストメッシュに登録し、投稿したいSNSアカウントをポストメッシュのダッシュボードで連携し、APIキーを発行する必要がある（運営者側では一切関与・管理しない）
- 本アプリ側のパスワードは全購入者共通の1つを運用する設計（`JIDOUTOUKOU_TOOL_PASSWORD`環境変数、`/tools/shukyaku`・`/tools/kanyu`と同じ運用）で、購入者ごとの個別発行・失効はできない。漏洩等が疑われる場合は、環境変数を変更して再デプロイすれば一斉に無効化できる
- ポストメッシュのAPI仕様（エンドポイント・リクエスト形式）は、同サービスが公開しているOpenAPI仕様（`https://post-mesh.com/openapi.json`）を直接参照して実装した。将来ポストメッシュ側の仕様が変わった場合は、同URLを再確認して追従する必要がある
- 投稿本文は、選んだすべてのSNSアカウントに同じ文面で送られる（プラットフォームごとの文字数上限はUI上に表示するのみで、実際の制限はポストメッシュ側のバリデーションに委ねている）
- ツールでのAI下書き生成には、別途購入者自身のAIプロバイダ（OpenAI・Anthropic）のAPIキーが必要。つまり本ツールの利用には、ポストメッシュ・AIプロバイダという2つの外部サービスへの別々の登録・支払いが購入者側に発生する。この点は出品ページ・購入後本文の両方に明記する
- 本番環境でのテストは、実際のポストメッシュAPIキーを取得していないため行えていない。ローカルでは、ダミーのAPIキーで実際に`https://post-mesh.com`へリクエストが届き、本物の`Invalid API key`エラーが返ることを確認し、中継処理そのものが正しく実装されていることを検証した（`lib/aiproxy.js`のOpenAI/Anthropic連携と同じ検証方法）

## 運用上の注意

- 投稿内容は、必ず購入者自身が目を通してから送信する（AIの下書き機能を使った場合は特に）
- MLM・副業初心者という読み手に対して、誠実で役に立つ内容を心がけ、押し売り感のある投稿は避ける
- エンゲージメント自動化（いいね・フォロー・コメント返信）は、将来的に要望があっても、SNS各社の規約抵触リスクを理由に実装を見送ることを推奨する
