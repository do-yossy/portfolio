# ミチシルベ 販売手法案

> これは「ミチシルベ」自体をどう売るかの**提案**です。数字（価格・目標件数・広告予算など）は運営者が決めるものなので断定せず、論点として挙げています。実績・お客様の声は、実際に得られたもの以外は載せない前提で構成しています。

## 1. 前提：誰に売るか

商品自体（`lib/personas.js`）が既に4つの購入者属性を定義しており、これがそのままターゲット像として使えます。

| 属性 | 状態 | 刺さる訴求 |
|---|---|---|
| ビジネスもAIもはじめて | 商品を売った経験もAI利用経験もほぼない | 「専門用語なしで、1ステップずつ」「一人で悩まなくていい」 |
| ビジネス経験はあるがAIははじめて | 販売・企画経験あり、AIは未経験 | 「経験をAIで一気に商品化できる」「作業時間の短縮」 |
| AIは使えるが商品販売ははじめて | ChatGPT等は日常利用、販売は未経験 | 「知識の抜け漏れをGATEが教えてくれる」「迷わず販売まで行ける」 |
| どちらも経験がある | 両方経験あり、効率よく進めたい | 「型に沿えば早い」「商品2・3もすぐ作れる」 |

初期に最も刺さりやすいのは「ビジネスもAIもはじめて」「AIは使えるが商品販売ははじめて」の2層（AIブームに関心はあるが行動に移せていない層）と想定されますが、これは仮説であり、実際の反応を見て検証が必要です。

## 2. 価値提案（すでに製品に実装済みの事実ベース）

- 90日・GATE1〜10という区切りが明確で、「何から手をつければいいかわからない」を解消する
- AIプロンプトが一式、選択式入力つきで用意されており、白紙から書く必要がない
- 進捗・マイ商品・GATE判定がアプリ内に保存され、迷ったら`/guide`でいつでも操作方法を確認できる
- 1日30分ペースが基本だが、前のめりに進めたい人も止めない設計（トップページに明記済み）

新規性を誇張せず、「迷わず最後まで進める設計そのもの」を主軸に据えるのが誠実で、かつ他のAI副業系コンテンツとの差別化にもなります。

## 3. 販売チャネル・手法（オンライン施策のみで構成）

対面での営業・イベントは前提とせず、すべてオンラインで完結する施策に絞って整理します。広告予算をかけない前提で、まず着手できるものから並べています。

### 3-1. コンテンツ発信（SNS）
- **note**：長文でのノウハウ・体験談発信に向く媒体。GATEの一部を無料公開（例：No.2「自分の商品を見つける」の質問だけ紹介）、購入者の許可を得たBefore/After事例、運営者自身が別ジャンルで実際にGATEを回して商品化する過程を実況する、など。記事の最後に必ず3-2のランディングページへの導線を置く。
- **X（Twitter）**：短文・スレッドでの日々の発信。ノウハウの一部を切り出して投稿し、続きはnoteやLPに誘導する。
- **Instagram**：GATEロードマップやマイ商品画面など、進捗が視覚的に伝わるスクリーンショットが向く。
- **YouTube・ショート動画（YouTube Shorts / TikTok）**：`/guide`と同じ内容（実際の画面操作）を動画で見せると、文章より「自分にも操作できそう」という安心感を伝えやすい。

### 3-2. ランディングページ（自社の着地点）
今回作成した1ページ完結のランディングページを、SNS・noteなどすべての発信からの共通の着地点として使う。「お問い合わせ」ボタンから既存の`/contact`に直接つながる導線は実装済み。

### 3-3. オンラインコミュニティでの発信
AI活用・副業系のオンラインサロン、Discordサーバーなど、オンラインで完結する場で「実際に手を動かして商品化まで行けるツール」として紹介する。

### 3-4. 既存オンラインチャネルとの連携
株式会社Social Qualityの既存のオンライン発信チャネル（求人・営業関連のSNSアカウントやサイトなど）があれば、そこからの導線を作る（新規に一から集客するより低コスト）。

### 3-5. メール・LINE公式アカウントでのフォロー
`/contact`経由で問い合わせをくれた見込み客に対し、メールやLINE公式アカウントで継続的に情報発信し、関係を作ってから案内する（届いてすぐ売り込まない）。

### 3-6. 紹介・口コミ（オンラインで完結）
購入者が自分の商品を実際に販売できた場合、その体験をSNS上で共有してもらう、または紹介リンク経由での申込みを案内するなど、対面を介さずオンラインで完結する紹介導線を用意する（フェーズ2で詳述）。

広告出稿（SNS広告・検索広告等）は、上記の無料オンライン施策で反応（申込み・問い合わせ数）を検証してから検討するのが安全です。最初から広告費を前提にしないことを推奨します。

## 4. 集客〜購入までの導線（ファネル案）

```
知る（SNS/note/紹介） → ランディングページ → 無料で体験できる何か → お問い合わせ → 決済 → メールアドレスを許可リストに登録 → 同じメールアドレスでアカウント作成 → 利用開始
```

- すべての発信（3-1）は、まず3-2のランディングページに着地させる。
- **無料で体験できる何か**の候補：
  - 「あなたはどのタイプ？」診断（`lib/personas.js`の4属性をそのままクイズ化できる）
  - GATE1の一部プロンプト（No.2「自分の商品を見つける」）を試せる簡易版ページ
  - 無料相談・LINE登録などで`/contact`につなげる
- 申込み〜決済は既存の運営フロー（お問い合わせ・銀行振込/メンバーペイの案内）に乗せ、決済確認後に運営者が`/admin/licenses`で購入時のメールアドレスを許可リストに登録する（今回実装したライセンス管理機能と直結）。購入者は同じメールアドレスでアカウント登録・ログインするだけで、キーの入力なしに利用開始できる。すべてオンラインで完結し、対面での手続きは発生しない。

## 5. ローンチの進め方（フェーズ案）

### フェーズ0：クローズドβ（最優先・数字より先にやるべきこと）
身近な数名（知人・既存の取引先の担当者など）に、実費または大幅割引で使ってもらい、実際に最後まで進めてもらう。ここで得られるのは:
- 本物の「使ってみた感想」「Before/After」（これが揃うまでは対外的に実績や感想を謳わない）
- つまずきポイントの実地確認（`/guide`だけで足りるか等）

このフェーズを飛ばして広く売り出すと、未検証のままクレーム対応に追われるリスクがあるため、最初に必ず挟むことを推奨します。

### フェーズ1：コンテンツ発信による認知拡大
フェーズ0で得た本物の事例・感想を使い、note/X等で発信を開始。「無料で体験できる何か」からの申込み導線を計測し、どのチャネル・どの投稿が反応するかを見ながら発信量を調整する。

### フェーズ2：紹介・口コミでの拡大
利用者が実際に自分の商品を販売できた事例が増えてきたら、紹介の仕組み（例：紹介した人・された人の双方に何らかの特典）を検討する。特典の内容・金額は運営者判断のため、本書では踏み込まない。

## 6. 価格・提供形態まわりの論点

**決定済み**：
- 価格：500,000円（税別）
- 返金：理由を問わず一切対応しない（`legal/利用規約_案.md` 第8条に反映済み。成果・結果を保証しない旨の第9条の免責事項とあわせて整合させている。特定商取引法に基づく表記にも同じ内容を記載済み〈7章参照〉）

**引き続き検討が必要な項目**：
- 買い切りか、分割払いに対応するか
- フェーズ0のクローズドβ価格と、正式価格の関係（早期割引にするか）
- 現行の許可リストは「1メールアドレス＝1アカウント」が前提。複数商品シリーズ展開時や、法人・チームでの複数利用ニーズが出た場合は別途設計が必要

## 7. 販売時に必要な法的表示（実装ではなく運営タスク）

デジタルコンテンツの有償販売には、**特定商取引法に基づく表記**（会社名・所在地・連絡先・価格・支払方法・返品条件等）の掲示が必要です。ドラフトは`legal/特定商取引法に基づく表記_案.md`として作成済みで、返金条件・支払方法・価格等の主要項目は`legal/利用規約_案.md`と揃えて記載済みです。残るメールアドレス・制定日等のプレースホルダーを運営者が埋めたうえで、販売ページ（noteやLPなど、販売に使う場所）に掲載してください。

4. フェーズ0の感想・Before/Afterを素材化し、フェーズ1の発信内容を作る
